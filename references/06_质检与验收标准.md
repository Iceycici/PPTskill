# 06 · 质检与验收标准（双闸门）

> 来源：2026-09-17 zcode 会话三轮实战质检流程定稿（84 页初版质检 → 删页重编质检 → 通篇校对质检）。视觉验收的 judge 子代理机制参考 ZCode 内置交付协议；程序化检查项为本会话 verify 系列脚本（verify_all/verify_final/verify_v4）的规则沉淀。

## 0. 总原则

1. **双闸门缺一不可**：程序化校验（脚本、可重复、穷举）+ 视觉复验（读渲染图、查程序查不到的观感问题）。程序化通过 ≠ 完成。
2. **改一轮、验一轮**：每轮修改后立即校验涉改面，不带未验证的修改进入下一轮。
3. **质检结论要留痕**：写入交付说明"质量保障记录"节，检查项、结果、豁免项全部列明。

## 1. 第一闸门：程序化校验（scripts/verify_deck.py）

规则走 JSON 配置（格式见 `assets/verify规则.example.json`），标准检查项：

| # | 检查项 | 判据 |
|---|---|---|
| 1 | 页数守恒 | `len(prs.slides) == 期望页数`（删改后必须复核） |
| 2 | 旧片段零残留 | 每条 `(页码, 旧子串)` 在该页全文（含表格、备注）中出现即 FAIL |
| 3 | 编号上界扫描 | 正则 `场景\s*(\d+)`、`练习\s*(\d+)` 等序列，值 > 上界即 FAIL（删页重编后必查） |
| 4 | kicker 连续性 | 场景 kicker 序列必须是排序后 1..N 连续；练习 kicker 必须恰为 range(1,N+1) |
| 5 | 页码=页序 | 右下角数字文本框（top>7"、left>12" 位置）与 slide 序号逐一相等 |
| 6 | 页脚唯一形态 | 页脚文本集合 == {课程名}，任何变体（悬挂间隔号、尾巴）即 FAIL |
| 7 | 白名单豁免 | `WHITELIST = [(页码, 允许关键词), ...]`：合法残留（如提示词例句里的"头脑风暴会议"）在指定页豁免，越页出现仍 FAIL |
| 8 | 结构性数量宣称 | "5 种表现""共 9 题""13 道"等数量词与实际结构一致 |
| 9 | 模板卡逐字抽查 | 引用语料（模板/金句）在指定页仍逐字存在——防校对误伤 |
| 10 | 备注回归 | 无连续双空格；`"C :"`、`"http s"` 不存在（空格规范化未破坏路径/URL） |
| 11 | 语义残留黑名单 | 项目级禁用词清单（如已删场景的专名"头脑风暴公式""万圣节方案"），出现即 FAIL（白名单豁免优先） |

**通过标准**：以上全部 PASS，输出残留清单为空（豁免项单列）。

## 2. 第二闸门：视觉复验

### 2.1 渲染

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/render_all.ps1 -Pptx <路径> -OutDir render_xxx
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/render_pages.ps1 -Pptx <路径> -OutDir render_xxx -Pages @(2,31,58)
```

- 分辨率 1600×900；命名 `s<页码>.png`；
- 复审只渲染涉改页（审阅-修复循环提速的关键）；
- PNG 命名规则：全量渲染补零（s01），抽页可不补零——读图时两种都要试。

### 2.2 逐页核对清单（读图时逐项过）

1. 文字截断/溢出卡片边界；
2. 元素重叠（文字压文字、图文互压、横幅压表格）；
3. 编号正确（流程步骤序号、大数字水印、页码、kicker 编号）；
4. 表格完整（行数、表头、斑马纹、列对齐）；
5. 配色/字体一致性（kicker 颜色、金句条形态、列表符）；
6. 截图清晰无拉伸变形、图注在位；
7. 改动点逐一对照（新文本在位、旧文本消失）。

### 2.3 复验方式

- 有 judge 子代理/读图通道时：把渲染 PNG 交给视觉代理，按页返回 pass/fail + 证据；
- 通道不可用时降级：Read 读图 → 逐页人工/主代理核对，仍按上述清单执行；
- **每页返回明确结论**（PASS / FAIL+具体位置），FAIL 修复后只重渲染该页复验，直至全 PASS。

### 2.4 已知良性误报（豁免，不算 FAIL）

- 篇章页大号半透明水印数字（有意设计）；
- check_layout 的 CJK 宽度估算在加粗大字号下的误差（以渲染图为准）。

## 3. 修复循环

```
发现缺陷 → 记录（页码|现象|根因）→ 定点修复（python-pptx 原位）→ 重渲染涉改页 → 复验
     ↑                                                              ↓
     └──────────────── 直至全 PASS ←────────────────────────────────┘
```

典型缺陷与修法（真实案例）：
| 缺陷 | 修法 |
|---|---|
| 底部横幅遮挡正文 | 内容组件里横幅 y 下移 / 正文区缩高 |
| 流程编号重启 1-N | flow 组件加 `start` 参数 |
| 表格残行删不掉 | `tr.getparent().remove(tr)`（见 references/04 第 6 节） |
| 类型列错位 | 按行号重写单元格文本+颜色（首 run 收拢法） |
| 大小写/悬挂标点 | polish_notes.py / replace_text.py 清单化修正 |
