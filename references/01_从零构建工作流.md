# 01 · 从零构建工作流（主线 A 细则）

> 来源：2026-09-17 zcode 会话实战沉淀（69 页中文教学课件《AI提示词工程：从新手到高手》全流程）。
> 设计原则部分参考官方技能 document-skills:pptx 0.1.4（Z.AI）的 Part 1 设计最佳实践，已按中文课件场景改写。

## A1 素材入库（不可跳过）

1. 把用户提供的讲义/笔记/docx **逐字**复制到工作目录 `sources/` 子目录，一个来源一个文件，文件名保留原名的编号前缀（如 `1.1AI新手与AI高级用户.md`），便于溯源。
2. docx 提取用 python-docx（`Document(path)` 遍历 `paragraphs` 与 `tables`），**不要用 Read 工具直接读 docx 二进制**。
3. 建立 `sources/_templates.md`：把所有提示词模板、金句、公式按来源章节归集，标注出处行号。这些是后续 `promptCard` 组件的内容库，**必须逐字**。
4. 建立两个图片索引（如嵌入截图）：
   - `_image_map.json`：`{ "源md文件名": ["../images/module_N/图.jpg", ...] }`
   - `_image_dims.json`：`{ "图文件名": [宽px, 高px, 宽高比] }`，排版时按 `h = w/ar` 放图，防拉伸。

**红线**：整理阶段禁止"顺手润色"。发现原资料口语化表述（如"最最最重要~"）先记录到《文字修改说明》清单，构建时统一按书面语体处理，且只改表达不改事实。

## A2 提取结构范式

用户提供参照文档时（例如某学习笔记的"三段式"），提取以下要素形成大纲表：

| 要素 | 要回答的问题 |
|---|---|
| 篇章结构 | 分几篇/几部分？每篇的职能？ |
| 段内模式 | 每节内部按什么顺序展开（如 作用→写法→范例 / 场景→模板→反例）？ |
| 编号体系 | 有哪些编号序列（篇/章/场景/练习），起始与对应关系？ |
| 结构性约定 | 是否"每个单元至少配一个练习"之类的硬约束？ |
| 版式特征 | 用户手动编辑过的 kicker/页眉写法、目录样式 |

**结构性约定是硬约束**：后续每次增删都要复查（如删了一个场景，对应练习与"每场景≥1 题"是否仍成立）。

## A3 确定设计令牌

开工前与用户确认三件事（源自官方 pptx 技能"Decide three things before you start"，改写）：
① 内容驱动配色（学术深蓝/活力橙等）；② 主次不等权（每页一个视觉焦点）；③ 明暗对比 + 贯穿母题（如篇章色 + 深蓝金句条）。

然后把全部设计决策集中为令牌（参考 `assets/deck-tokens.example.json` 与 `assets/lib-template.js` 顶部令牌区）：

- 配色 `C`：底色/标题色/正文色/弱化色/卡片底/线条色，另加语义色 good/bad 及其浅底；
- 篇章色 `PART`：`{1: {color, tint, dark, label}, 2: ..., 3: ...}`，篇章页与该篇所有页面的 kicker 用同一色；
- 字体 `F`：中文课件统一微软雅黑（python-pptx 侧务必同时设 `a:ea` 东亚字体，否则中文回落默认字体）；
- 版式常量：`W=13.33, H=7.5`（`LAYOUT_WIDE`），页码框位置（右下 x≈12.35", y≈7.12"）、页脚文案。

**铁律**：`pres.layout = "LAYOUT_WIDE"` 必须显式设置；令牌只在令牌区定义一次，页面代码里不得出现裸色值。

## A4 组件化构建

目录结构（参考 `assets/build-template.js`）：

```
deck/
  lib.js        # 设计系统：令牌 + 12 组件，module.exports
  build.js      # 入口：new pptxgen → 设 layout → 按序 require 各篇章模块 → writeFile
  p0_intro.js   # 每个模块导出 function(pres, L)，内部用 L.next() 领页码
  p1_part1.js / p2a.js / p2b.js / p3_part3.js / p4_closing.js
```

12 个标准组件及使用场景：

| 组件 | 场景 |
|---|---|
| `content(pres,{part,kicker,title,notes})` | 内容页骨架：kicker+标题+页脚+页码+备注 |
| `divider(pres,{num,title,subtitle,items,part})` | 篇章页：大号水印数字+篇章色+条目列表 |
| `card / chip / bullets` | 卡片底板 / 胶囊标签 / 列表（支持 [加粗lead, 正文] 二元组） |
| `numRows / flow` | 纵向编号行 / 横向步骤链（支持 `start` 参数，删页重编后编号可从 6 起） |
| `promptCard` | 深蓝提示词模板卡：金色 label + 多行模板正文（内容取自 _templates.md） |
| `versus` | 双栏对比（左"反例/不加引导"，右"正例/更好做法"） |
| `quote` | 深蓝金句条 |
| `table` | 表头深色 + 斑马纹；单元格可传对象定制颜色加粗 |
| `shot` | 截图+图注；按文件名首字符自动定位子目录 |

每页必写演讲者备注（`addNotes`）：讲解要点 + 内容出处（"来源：讲义1.4"）。这是交付说明"覆盖核对表"的依据。

**布局守则**（官方 Part 1 精华）：每页一个焦点；图不与文字抢位（图占 40–60% 时文字只留短句）；正文字号下限 11.5pt；卡片间距 ≥0.3"；列表项数 ≤5，超了拆两栏；流程步骤链卡片等宽居中，箭头独立绘制。

## A5 截图嵌入

- 用 `_image_map.json` 找候选图，`_image_dims.json` 查宽高比；
- 每张截图配图注（"图：xxx"），图注字号 10–10.5pt 灰色；
- 嵌入数量"精选"：每章 1–3 张关键操作图即可，宁可少而清楚。

## A6 兼容修复（必做）

pptxgenjs 在 run 级富文本段落会产出重复 `<a:pPr>`，PowerPoint 打开时报"需要修复"。构建后立即：

```
python scripts/fix_ppr.py 输出.pptx
```

脚本在每个 `<a:p>` 块内只保留第一个 pPr，原位重写 zip（tmp→move），打印修复的 slide 数。**跳过这步 = 用户第一次打开就看到修复弹窗。**

## A7 程序化预检

```
python scripts/check_layout.py 输出.pptx
```

检查三项：文本溢出（估算高度 > 框高×1.08）、越界（超出画布）、重叠（两形状交叠 > 0.25"×0.18"）。篇章页大号水印数字是**有意设计**，属已知误报，忽略即可。

## A8 渲染与视觉验收

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/render_all.ps1 -Pptx <pptx路径> -OutDir render
```

- 全量出图后逐页视觉核验：文字截断/遮挡、图文重叠、流程编号、错别字、页面元素越界；
- 缺陷记录格式：页码 | 现象 | 根因 | 修复方式；修复后**只重渲染涉改页**（`render_pages.ps1`）复验；
- 全部通过才算构建完成。视觉验收方法详见 `references/06_质检与验收标准.md`。

按 `assets/交付说明模板.md` 写交付说明；构建脚本与 sources 留在交付目录中作为"再生成能力"移交。
